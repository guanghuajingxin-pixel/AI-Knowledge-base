# 物料库抠图接入方案与配置指南

核对日期：2026-09-29。本文是接入设计与操作指导；尚未部署 SaaS 适配服务，也未用抠图 SaaS 验证附件零件。现有百炼图片 Embedding 的真实上传与检索已验证。

## 1. 推荐决策

**优先方案：阿里云视觉智能开放平台「通用分割」+ 轻量 HTTP 适配服务 + 已配置的百炼图片 Embedding。**

不需要训练模型，也不需要先搭 Dify、n8n 或 ComfyUI 工作流。抠图是一段确定的处理过程，直接放在现有 Celery 图片任务调用链中即可。适配服务只转换鉴权、文件和返回格式，不加载模型，可部署为一个小型容器或 HTTP 云函数。

| 路线 | 适合情况 | 需要准备 | 建议 |
| --- | --- | --- | --- |
| 阿里云视觉智能通用分割 | 希望沿用阿里云账号、国内部署接入 | 开通独立分割服务、服务身份、协议适配 | 本项目优先试用 |
| Photoroom Remove Background API | 希望用 API Key 和文件直传快速评估 | Photoroom 账号/API Key、协议适配、服务网络可达 | SaaS 备选 |
| 自建 BiRefNet 预训练推理服务 | 图片不能离开企业内网，或有稳定大批量任务 | 推理部署、模型权重、算力与维护 | 有数据出域限制时选用 |
| VL 定位 + SAM 2 分割 | 多个物体，需要按语义指定其中一个 | VL API、分割推理服务、坐标转换 | 后续增强，不作为第一步 |

选型建议基于项目部署条件，并不代表已证明某服务对工业零件效果最好。先用真实样本比较孔洞、反光和细薄边缘，再决定正式供应商。费用按所选区域、套餐与实际调用量在开通页面确认，不写死报价。

阿里云通用分割提供主体分离能力；Photoroom 提供专用去背景 API。[阿里云接口说明](https://help.aliyun.com/en/viapi/developer-reference/api-k8cs8t)、[Photoroom 快速开始](https://docs.photoroom.com/remove-background-api-basic-plan/quickstart-guide)。

## 2. 为什么现在不能直接填一个云厂商 URL

当前项目抠图协议是：

```http
POST /remove-background
Authorization: Bearer <适配服务访问令牌>
Content-Type: multipart/form-data

file=<PNG 文件>
model=<组件模型标识>
```

响应必须是与输入文件**同宽同高的 RGBA PNG**，或 `{"image_base64":"..."}`。PNG 的 alpha 通道表示保留/去除区域。项目不直接下载响应中的远端 URL。

但阿里云采用 OpenAPI 签名鉴权，返回结果地址；Photoroom 使用 `x-api-key` 和 `image_file`。因此，**现有「自定义 HTTP」不是任意第三方 API 的通用接入器**。直接填厂商地址会因为鉴权、字段或响应格式不同而失败。

已有能力：组件保存/查看/测试、上传预加工开关、HTTP 抠图调用、透明图保存、标准化、向量化和检索。

待补能力：任一厂商的协议适配与部署。本文中的 `/remove-background` 是拟部署服务的路径，不是当前 kb-api 已存在的接口。

## 3. 首选方案：阿里云 SaaS

### 3.1 管理员准备

1. 在阿里云视觉智能开放平台开通「分割抠图」服务，选择 **通用分割 `SegmentCommonImage`**，先在产品体验页试附件零件。
2. 为适配服务配置专用 RAM 身份，权限按实际调用授予；使用部署环境提供的角色凭据，或由后端安全保存 AccessKey ID / Secret。
3. 注意：**百炼的 `sk-...` API Key 只用于现有 Embedding，不能代替这里的阿里云 OpenAPI 凭据。** 不把 AccessKey Secret 填入前端的单个 API Key 字段。
4. 从该接口的 OpenAPI Explorer 生成 Python SDK 示例，按生成结果固定 SDK 版本、区域和凭据方式。

官方入口与参数以[通用分割文档](https://help.aliyun.com/en/viapi/developer-reference/api-k8cs8t)、[SDK 调用示例](https://help.aliyun.com/zh/viapi/use-cases/general-image-segmentation)及 OpenAPI Explorer 为准。

### 3.2 适配服务实现要求（开发人员）

建议接口：`POST /remove-background`，监听独立服务端口，例如 8015。

处理步骤：

1. 校验来自 kb-api / worker 的 Bearer 令牌、图片体积和像素数，读取 `file`。项目已经执行 EXIF 方向校正和用户框选，记录输入尺寸 W×H。
2. 保存原始 RGB 像素副本；为云服务制作等比缩小的工作图，不做补画或美化。
3. 使用官方 imageseg SDK 调用 `SegmentCommonImage`，传 `ReturnForm=mask`，获取分割蒙版结果。
4. 及时读取 SDK 响应的结果图，校验内容与尺寸；仅接受来自该次可信云 API 响应的结果地址，对下载主机、重定向、超时和体积做限制。不要实现接收任意外部 URL 的下载接口。
5. 如果工作图经过缩小，把蒙版映射回 W×H；原始 RGB 保持不变，以蒙版作为 alpha，输出 RGBA PNG。放大蒙版不会恢复已经损失的小孔和细边，必须做样本验收。
6. 返回 `Content-Type: image/png` 的二进制。不要把云厂商 JSON 或临时 URL 原样返回给项目。

该 API 当前要求输入不超过 3 MB、最长边不超过 1999 像素；结果地址有时效。适配层需要压缩工作图，并在限制内处理异常小图；不得将云服务工作图尺寸直接当作最终输出尺寸。[输入限制与结果说明](https://help.aliyun.com/en/viapi/developer-reference/api-k8cs8t)。

这一步采用蒙版与原图合成，目的是保留原始材质纹理和零件形状；不要自动填孔、平滑掉槽口、去掉与主体断开的真实细小部件。蒙版仍可能误分，不能只靠“返回 200”判断抠图质量。

### 3.3 部署清单

建议独立容器名 `material-remover`，与 kb-api、worker 使用同一内网。部署参数由适配实现读取，以下是**建议变量，不是现有应用已有配置**：

| 参数 | 用途 |
| --- | --- |
| `REMOVER_ACCESS_TOKEN` | 项目调用适配服务的 Bearer 令牌 |
| 阿里云 SDK 凭据配置 | 通过 RAM 角色或部署环境注入，不写代码和镜像 |
| `REMOVER_BACKEND=aliyun-common` | 固定供应商与适配策略 |
| `REMOVER_POLICY_VERSION=v1` | 固定缩放、蒙版及后处理规则 |

健康检查 `/healthz` 只检查服务存活；实际模型连通性由项目「测试连通性」验证。适配服务不需要 GPU。生产请求总时长应低于现有组件 90 秒超时，预留云服务请求和结果下载时间；为 429/临时错误设置有上限的重试，鉴权错误直接返回。

若使用云函数，暴露同一 multipart HTTP 接口，检查网关上传大小、同步超时和响应体积限制。函数计算只托管适配代码，算法仍由 SaaS 执行。

### 3.4 在项目里填写什么

**先部署适配服务，再执行以下操作。**

进入「系统配置 → 图片组件 → 新增组件」：

| 字段 | 示例值 |
| --- | --- |
| 组件名称 | 阿里云通用分割 v1 |
| 用途 | 图片抠图 |
| 服务协议 | 自定义 HTTP |
| 接口地址 | `http://material-remover:8015/remove-background`（容器同网示例） |
| 模型名称 | `aliyun-segment-common-v1`（适配服务识别的固定标识） |
| API Key | `REMOVER_ACCESS_TOKEN` 对应令牌，不是百炼 Key / 阿里云 AK Secret |
| 向量维度 | 抠图不使用，页面禁用即可 |

URL 必须同时被 **kb-api 和 Celery worker** 访问。本机开发时可用 `http://127.0.0.1:8015/remove-background`；容器内 `127.0.0.1` 指向容器自身，不能直接沿用本机地址。跨机器部署使用实际内网 DNS/HTTPS 地址。

保存后：

1. 「查看配置 → 测试连通性」：验证内置图片能得到有效透明结果。该测试会真实调用 SaaS。
2. 「测试图片」：上传附件原图，检查金属零件的边缘和孔洞。内置圆形图若被服务拒绝识别，使用真实零件图分辨“模型不接受探针”与“网络/鉴权失败”。当前连通性测试同时校验输出，不只是网络探测。
3. 在「知识库 → 物料库 → 库设置」选择现有百炼向量组件和新增抠图组件，打开默认预加工。
4. 上传图片并勾选预加工，等待完成，分别查看原图、透明前景、标准图。
5. 已有原图索引不会自动改变。对旧图片执行重新处理，并选择采用当前库组件、启用预加工；重新处理期间该图暂不提供旧索引检索。
6. 在「检索测试」上传查询照片。系统按入库组件规则自动处理查询图，无需用户再次手动配置查询侧模型。

## 4. SaaS 备选：Photoroom

Photoroom 的专用去背景接口为 `POST https://sdk.photoroom.com/v1/segment`，鉴权为 `x-api-key`，上传字段为 `image_file`。它的去背景接口与生成式编辑接口应分开使用。[官方快速开始](https://docs.photoroom.com/remove-background-api-basic-plan/quickstart-guide)。

开发接入时，将项目 Bearer 令牌验证与 Photoroom Key 分开：前者验证本项目的请求，后者仅保存在适配服务。把 `file` 转为 `image_file`，指定 PNG、关闭裁剪与背景替换，检查实际响应尺寸再返回。

为了严格保留原图，可请求 `channels=alpha` 获取蒙版，与输入原始 RGB 合成；但官方说明仅蒙版输出不带同样的边缘 matting，须评估细边质量。禁止启用会改变颜色的去绿幕等附加效果。[蒙版接口说明](https://docs.photoroom.com/remove-background-api-basic-plan/download-the-segmentation-mask)。

供应商允许的体积和格式不等于项目限制，适配输出仍需符合本项目 20 MB、2000 万像素以及同尺寸透明 PNG 约定。[供应商格式限制](https://docs.photoroom.com/remove-background-api-basic-plan/file-size-resolution-and-format)。

先在供应商控制台取得 Key，完成样本对照后再购买适合的套餐；样本评估包括从实际部署网络的可达性、耗时与图片处理条款。当前项目未内置该供应商协议，仍需同样的适配步骤。

## 5. 不使用 SaaS：自建预训练 BiRefNet

可以部署现成的 BiRefNet 权重做推理，无需训练。官方项目提供预训练模型和推理入口。[BiRefNet 官方仓库](https://github.com/ZhengPeng7/BiRefNet)。

建议部署方式：

1. 单独推理容器，固定代码提交、权重版本与依赖；核对所选权重的使用许可。
2. 模型在启动时加载一次；不要每张图重复下载或初始化，也不放进 kb-api / Celery 主进程。
3. 输出蒙版，映射至原始输入尺寸，与原图 RGB 合成透明 PNG。
4. 暴露与第 2 节相同的接口，因此项目侧仍填「自定义 HTTP」。
5. 从单并发开始，实测代表性图片的耗时和显存后决定实例规格与并发，不承诺未经压测的 GPU 配置。

这条路线减少向外部抠图供应商发送图片，但仍需算力、监控和维护。**如果继续使用百炼 Embedding，处理后的图片仍会发送到百炼；整个链路完全内网还需要替换向量服务。**

## 6. 普通 VL 大模型能否直接抠图

普通视觉理解接口适合回答“物体在哪里”“有几个零件”，部分模型能返回框或点坐标。坐标不是逐像素透明蒙版；不要要求模型输出一长串 PNG base64 来冒充可靠抠图结果。Qwen 视觉文档提供定位能力，坐标体系随模型不同，需要按当前模型规范转换。[Qwen 视觉理解](https://help.aliyun.com/zh/model-studio/vision)。

推荐增强路线是：

```text
照片 + 用户描述（例如“中间的金属零件”）
  → VL 返回目标框
  → 校验坐标、映射到原图
  → SAM 2 接收框/点并输出分割蒙版
  → 蒙版与原始 RGB 合成
  → 现有标准化 → Embedding → 检索
```

SAM 2 提供预训练分割推理能力，可用提示控制目标。[SAM 2 官方仓库](https://github.com/facebookresearch/sam2)。该组合是本项目的设计建议，尚未接入或验证。若 VL 返回多个同等候选，让用户框选；不要静默选择任意物体。

单个零件的照片优先直接使用抠图模型；复杂多物体场景再引入 VL。通用生成式编辑虽然可能“去掉背景”，但不适合作为本场景默认路径：物料检索需要保持真实孔槽、螺纹及边缘，不能靠视觉上相似的重绘代替原图结构。这是基于任务目标的工程取舍。

## 7. 针对附件零件的验收方法

特别注意：黑色区域不一定是背景。圆筒内壁、凹槽中的暗面属于零件，应保留；只有实际露出桌面的开口应去除。不能把所有暗色孔洞都变成透明。

建议第一轮用 30–50 张真实物料照片做选型小测，包括独立拍摄的同料不同角度、相似异料、复杂桌面、金属反光、细槽口和多个物体。此规模只是试点建议，不代表已达到生产准确率。

| 验收层次 | 检查内容 | 通过标准 |
| --- | --- | --- |
| 协议 | 鉴权、维度、格式、alpha、超时、失败提示 | 明确返回可用图或可解释错误，失败不伪装成功 |
| 抠图 | 背景、细边、圆筒暗部、真实开口 | 人工逐张检查关键结构，无补画；失败可框选重试 |
| 检索 | 同料不同拍摄与相似异料 | 对照原图/框选/抠图三组的 Recall@5、Top1 和误召回 |
| 性能 | 上传与查询耗时、P95、失败率、成本 | 按业务并发预算设阈值并实测 |

固定同一 Embedding 模型，对三种预处理做对照。不能用“同一张图检索自己”的高分代替识别效果验收，也不应预设抠图必定提高检索率。

粗略成本模型：抠图调用量 = 新图片首次处理 + 人工重处理 + 查询次数 × 需要抠图的配置组数 + 测试/重试；乘供应商单次价格后另计适配运行费用。现有查询按配置组处理，混用多个版本会增加调用次数。未来可按“图像摘要 + 框选 + 抠图组件版本”缓存，但当前未实现跨请求缓存。

## 8. 故障排查

| 现象 | 优先检查 |
| --- | --- |
| 鉴权失败 | 项目→适配服务的令牌，适配服务→云供应商的凭据分别核对；百炼 Key 不通用 |
| 服务无法连接 | API 与 worker 都能否访问该地址、端口及容器 DNS |
| 返回 URL / JSON 导致处理失败 | 适配层是否下载结果并转换为透明 PNG，而非直传供应商响应 |
| 尺寸不一致 | 云端缩小/裁剪后是否将蒙版正确映射回适配输入尺寸 |
| 完全不透明 | 是否误选白底/JPEG 输出，或前景识别失败 |
| 零件缺损 | 查看原图和 alpha，尝试框选；仍失败则明确不启用本张预加工 |
| 旧图片效果没变 | 修改库默认不重建旧图，需要选择当前库组件重新处理 |

## 9. 实施交付边界

建议先完成一个阿里云适配服务及部署配置，用上述样本验收；其后再考虑把供应商类型原生加入「图片组件」配置页，避免管理员理解接口转换。

本方案阶段不改数据库和现有业务代码、不训练或下载模型、不新开通付费服务。下一步落地所需外部条件是：开通视觉智能分割能力，并为适配服务准备可调用该能力的后端身份。无需重新配置已经成功的百炼 Embedding。
